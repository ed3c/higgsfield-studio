## 6. Process findings

- **F-26.** Stage B in round 3 globbed `pack-v2/evidence/*` and shipped round-2 scoring files, which could anchor a reviewer. Fixed in RUBRIC_V2R4 by a whitelist and a name guard. The guard then conflicted with completeness (F-39).
- **F-36.** Secrets existed only in a foreground shell and were shredded before the report arrived. Fix used in 4b: print passphrases only in the final text report and do not shred until that report is written. The orchestrator logs the stage-A hash before releasing stage B.
- **F-39.** The cited-file check looked only at the `evidence_file` field, so files named in limits text (`seg_v3_posthoc_informational.json`, `failure-cases.jsonl`) were absent; four claims also had a null `evidence_file`. No 4b gate was affected.
- **F-40.** The 4b reviewer disclosed that the agent harness auto-saved truncated command output (claim text and JSON excerpts, no media) to a private tool-output store. Not verified here (the store was not opened). Whether to purge it is an owner decision. Passphrases were passed as an env var.

Other process limits that still apply: same-uid box isolation is by instruction (`chmod 000` is defence in depth; encryption is the real protection); F-12 cannot be lifted while Grok Bot reviews Grok Bot work; F-15 (log + mtimes, no external witness) still describes the protocol evidence.
